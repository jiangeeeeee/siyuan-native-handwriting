# 源生笔迹 0.14.6：书写性能优化

更新日期：2026 年 11 月 8 日。

这一版主要解决长文档中笔迹越多、书写越慢的问题，并缩短打开书写模式后的首笔处理时间。

## 改了什么

- **按屏幕范围绘制。** 原来会为整篇文档创建笔迹 SVG 路径；现在只保留屏幕内及上下缓冲区的路径。滚动时补入附近笔迹，移除远处图形。空间索引用于快速找到当前区域的笔迹。
- **提前准备首笔画布。** 进入书写模式时分配并预热绘图缓冲区。落笔后立即绘制起点，避免再等待一帧。连续书写时优先处理当前笔迹，历史图形分批补入。
- **减少反复计算。** 未发生变化的同步数据保留原有对象；路径缓存限制容量；撤销记录只保存发生变化的笔迹。大文档的 JSON 解析放到后台线程，保存编码分批执行，让出主线程处理输入。
- **收紧内存占用。** 已完成的长笔画以双精度数值缓冲保存采样点，需要编辑时再展开；关闭的文档缓存及时释放。后台备份逐篇处理，避免同时保留所有文档。密集白板的小地图改为一张缩略图。

原有逐页保存、同步合并和备份格式保持兼容。这次分页的是屏幕图形；当前文档的原始采样仍会读取并紧凑缓存，尚未改成按屏幕区域从磁盘分页读取。坐标、压感和时间戳不做有损简化。

## 测试结果

同一浏览器测试环境，文档预置 10,000 笔，每笔 128 个采样点，共 128 万点；另写入 8 笔，并向下滚动 80,000 像素后返回。

| 项目 | 0.14.5 | 0.14.6 |
| --- | ---: | ---: |
| 首屏 SVG 笔迹路径数 | 10,000 | 40 |
| 远处滚动位置的路径数 | 10,008 | 62 |
| 首次渲染调用至两次动画帧结束 | 363.3 ms | 22.6 ms |
| 滚动后显示远处笔迹、返回原位置 | 通过 | 通过 |

在浏览器 4 倍 CPU 限速、可信笔输入事件测试中，首笔事件处理为 **3.2 ms**，事件时间戳至首次绘制提交为 **12.4 ms**；落笔时没有新增画布缓冲分配。这些数值来自浏览器自动化测试，不是平板笔尖接触屏幕至像素亮起的硬件延迟。

**59 项单元测试、108 项浏览器测试全部通过，正式构建通过。** 回归覆盖正文与白板书写、压感、笔迹对齐、滚动与缩放、圈选编辑、橡皮、撤销重做、图层、导出、存储及备份恢复。长文档测试另核验了采样点在缓存回收后的完整性。
